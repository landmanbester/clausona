# AGENTS.md — working on clausona

This file is the canonical guide for AI agents and new contributors. Read it before
changing anything. `CLAUDE.md`, `.cursor/rules/` and
`.github/copilot-instructions.md` point here.

## What this project is

clausona is a Node.js CLI + shell hook that lets one machine hold multiple Claude Code
accounts. Each account is a separate config directory; clausona symlinks the shared
parts (MCP servers, plugins, settings) and keeps the private parts private (credentials,
session history by default). `clausona use <name>` flips the active account; the
`claude()` shell wrapper applies it.

There is **no** daemon, server, or patched Claude Code. The whole product is:

1. a bundled Node CLI (`dist/index.js`), and
2. one shell function emitted by `clausona shell-init`.

## Golden rules (do not break these)

These encode real bugs that were fixed. Violating one is a regression.

1. **Never share `.claude.json` or `.credentials.json` between profiles.** On Linux and
   Windows, Claude Code stores OAuth tokens in `$CLAUDE_CONFIG_DIR/.credentials.json`.
   If it is symlinked to the primary, every profile authenticates as the primary and
   `use` appears to do nothing. Both names live in `BASE_SHARED_LINK_SKIP` in
   `src/lib/service.ts`.
2. **`jobs/` and `teams/` follow `projects/`.** They are session-keyed, so they must be
   shared exactly when `mergeSessions` is true. `sharedLinkSkipSet()` is the single
   place that decides this.
3. **Merge local session state into the primary before linking it away.**
   `setupSharedLinks` deletes a profile's real directory once it symlinks it. Call
   `mergeSessionState()` first (as `repairProfile` and `updateProfileConfig` do), or the
   user's background sessions/team records vanish.
4. **Write JSON atomically.** Use `writeJson` / `writeJsonIfChanged` / `atomicWrite`
   from `src/core/store.ts`. Never `writeFile(JSON.stringify(...))` directly.
5. **Serialise read-modify-write with `withFileLock`.** `profiles.json` and
   `usage.json` are touched by concurrent `claude` sessions; a lost update drops usage
   records. See `trackUsage`, `seedSeenSessions`, `saveRegistry`, `removeProfile`.
6. **Shell integration must `unalias claude` and preserve a user-set
   `CLAUDE_CONFIG_DIR`.** An alias shadows the wrapper; clobbering a user's exported
   value is surprising.
7. **Tests must be hermetic.** No network, no real `~/.claude`, no interactive login.
   Use `mkdtempSync`/tmpdir and clean up in `afterEach`. See `src/core/store.test.ts`.
8. **Keep the hot path cheap.** `claude` is launched constantly. The wrapper reads
   `~/.clausona/active-config` (no Node spawn) and `syncPluginsJson` skips no-op writes.
   Don't add per-launch work without a fast path.

## Setup

```bash
pnpm install
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest run
pnpm build       # esbuild -> dist/index.js (chmod +x)
pnpm test:watch
```

`dist/` is gitignored. Rebuild and re-copy it to the install location after changes:

```bash
pnpm build && cp dist/index.js ~/.local/share/clausona/index.js
```

## Definition of done

Before you consider a change complete:

- [ ] `pnpm typecheck` passes.
- [ ] `pnpm test` passes (add tests for new behaviour — see below).
- [ ] `pnpm build` succeeds.
- [ ] You did not violate a golden rule above.
- [ ] User-facing behaviour changes are reflected in `README.md`.
- [ ] Commit messages explain *why*, not just *what*.

## Architecture

See [`src/AGENTS.md`](src/AGENTS.md) for a module-by-module map and the guidance for
which files to touch for common tasks. High level:

- `src/index.tsx` — entry, argv parsing, CLI/TUI dispatch, `run` exec path.
- `src/commands.ts` — command table, flag validation, help text, `runCommand`.
- `src/lib/service.ts` — the core. Discovery, registry, shared links, repair, login,
  usage queries, shell init, uninstall.
- `src/core/` — `paths.ts` (config/keychain path rules), `store.ts` (atomic JSON +
  locks), `usage.ts` (period math), `track-usage.ts` (fingerprints), `doctor.ts`
  (symlink health), `registry.ts` (active profile), `shell.ts` (shell integration).
- `src/tui/` — Ink/React dashboard. UI only; logic belongs in `service.ts`.
- `src/types.ts` — shared types. Keep `DoctorIssue.kind` unions exhaustive.

### Data model

```
~/.clausona/profiles.json   Registry { primarySource, activeProfile, profiles }
~/.clausona/active-config   "__PRIMARY__" or a config dir (shell fast path)
~/.clausona/usage.json      UsageStore per profile: { records[], seenSessions }
~/.clausona/backups/<name>  snapshot taken before linking a profile
```

`profiles.json` is the source of truth. `active-config` is a cache that is always
regenerated by `saveRegistry`; if it is missing or stale the shell falls back to Node.

### Path rules

Use `claudeJsonPathForConfigDir` / `keychainServiceForConfigDir` from
`src/core/paths.ts` — never hand-build `~/.claude.json` or the keychain service name.
The primary's `.claude.json` lives at `~/.claude.json`, while secondary configs put it
inside their config dir.

## Testing conventions

- Colocate tests: `foo.ts` → `foo.test.ts` next to it.
- Pure functions get unit tests (`usage.ts`, `doctor.ts`, `paths.ts`,
  `validateProfileName`).
- Filesystem behaviour gets tmpdir tests (`store.ts`).
- Don't mock modules when a real temp directory is cheap.
- Prefer asserting on a specific field/kind over a whole-object snapshot.

## Common tasks

| Task | Touch |
|------|-------|
| Add a CLI command | `types.ts` (`ParsedCommand` if needed), `commands.ts` (table + help + `runCommand`), `service.ts` for logic, README command table |
| Add a `doctor` issue | `types.ts` `DoctorIssue.kind`, `core/doctor.ts` or `doctorProfiles`, `lib/format.ts` suggestion logic, test |
| Change what gets shared | `BASE_SHARED_LINK_SKIP` / `sharedLinkSkipSet()` in `service.ts`, README diagram, a tmpdir test |
| Change shell integration | `core/shell.ts` + `core/shell.test.ts` (assert on emitted strings) |
| Move usage math | `core/usage.ts` + `core/usage.test.ts` |

## Commit & PR conventions

- Small, focused commits. Messages use a `type: summary` prefix (`fix:`, `feat:`,
  `perf:`, `docs:`, `chore:`, `test:`, `refactor:`).
- Explain the user-visible effect and any migration/repair implications in the body.
- Do not commit `dist/`, `node_modules/`, or `~/.clausona` data.
- PRs should state which commands/tests you ran.

## Known footguns

- **`ANTHROPIC_API_KEY` overrides profiles.** It is a user environment issue, not a code
  bug; document it, don't silently unset it. (`clausona run` and the wrapper both pass
  the environment through.)
- **`doctor` removes broken symlinks as a side effect.** Intentional today; don't turn
  it into a file-deleting command without warning.
- **`execCommand` must stay error-safe.** A missing `secret-tool`/`security`/`claude`
  binary emits `error`, not `close`. Keep the `error` listener.
- **The primary `.claude.json` path is `~/.claude.json`**, but its credential is
  `~/.claude/.credentials.json`. Don't "fix" one to match the other.
- **Don't import `service.ts` from tests that spawn processes** without a temp HOME;
  module constants capture `homedir()` at import time.
